# Personal ERP · 全站交互设计语言（乔布斯式对象触控）

日期：2026-08-24 ｜ 状态：待审阅
范围：全站设计语言，分三期落地；本文档为唯一设计依据。

---

## 一、背景与目标

现状：界面以「椭圆按钮堆叠 + 文字标签」为主，卡片点击语义不统一（活动卡点击=编辑、资源卡点击=补充），核心流程存在断裂（产出链死亡、首启衔接缺失等，见附录 A 调研结论）。

目标：建立「卡片即对象」的全站设计语言——单击=状态主动词、双击=计时、长按=更多、右滑=推进、左滑=改约；引导内化于形态（零教程、零遮罩）；修复全部流程断裂。

## 二、设计宪法（不可违背）

1. **可达性单调递增**：任何现有操作在改造后必须仍可达。机制：长按菜单是**超集收容所**——被精简的按钮功能先迁入长按菜单（保底路径），手势只是额外捷径。删除等危险动作永不绑手势，保留 confirm。
2. **看板 + 日历日程是旗舰**：只增强不降级。拖拽跨列、冲突⚠标记、时间段显示全部保留。
3. **dayGuide 五步逻辑冻结**：welcome→goal→plan→acts→summary 流程、跳过记录、多目标多计划能力不动；只增加入口（setup 完成后自动进入、日历页手动唤起），不改既有行为。

### 引导内化三定律（替代一切教程系统）
- **形态即启示**：五态进度轨显示位置并暗示可推进；可滑动的卡在动作方向露出一丝底层色边（peek affordance）；资源卡上缘刻度线暗示连推加注。**不做呼吸提示条、首次遮罩、手势计数器**（`Prefs.gestures` 方案作废）。
- **空态即路标**：每个列表空态指向下一动作（逐屏文案见附录 B）。
- **反馈即确认**：触觉只在关键节点说「成了」，不说「该做什么」。

## 三、交互语法

### 第一层 · 卡片即对象
| 手势 | 动作 |
|---|---|
| 单击 | 状态主动词（Planned→开始 / Started→完成 / Completed→复盘 / Reviewed→归档） |
| 双击 | 🍅 计时 |
| 长按（≥500ms） | 更多菜单 |
| 🍅 按钮 | **保留原位**（计时是高频显性入口） |

### 第二层 · 滑动即状态流
| 手势 | 动作 | 说明 |
|---|---|---|
| 右滑 | 推进到下一态 | 卡片跟手位移露出「✓」层；需输入的节点（完成）松手弹 bottom-sheet，金额预填 |
| 左滑 | 改约 | 弹改期快捷面板 |

### 第三层 · 流程编排链
完成闭环一条手势链贯通：右滑 Started 卡 → 松手弹完成 sheet → 上滑确认 → 入账 + 触觉 + 余额数字滚动。
sheet 内**同时保留显式「完成入账」按钮**（可达性宪法兜底：会滑用手势，不会滑点按钮，两条路同终点）。
资源卡连推：按住上推 = 快速加注固定额度（+10/次），点卡为精确面板；连推仅作快捷路径，不替代精确输入。

### 手势安全边界
方向锁 12px + 触发阈值 64px；危险动作永不绑手势；prefs 提供全局手势开关（关闭回落纯点控）；卡片触摸优先结算为卡片手势，空白区才升级 Tab 切换（复用 main.js setupSwipe 的 closest 排除机制）。

## 四、各对象改动映射（零丢失对照）

| 对象 | 现有可达方式 | 改造后 |
|---|---|---|
| 活动卡·状态动词 | 底部状态按钮 | 单击卡 + 右滑 + 长按菜单 三通 |
| 活动卡·计时 | 🍅按钮 | **按钮保留** + 双击 + 长按菜单 |
| 活动卡·编辑 | 点击卡 | 长按菜单 |
| 活动卡·删除 | ⋯菜单 | 长按菜单（confirm 不变） |
| 活动卡·产出行发布/归档 | 行内小按钮 | **原样保留**（流程关键主动词） |
| 资源卡·补充 | 点击卡 | 不变 |
| 资源卡·编辑/停用/删除 | 卡内按钮 | 迁入长按菜单 |
| 商品消费 / 兑换 / 冲正 | 各自按钮 | 原样保留（低频精确操作不手势化） |
| 日历议程行 | 点击跳转 | 不变，新增长按菜单 |
| dayGuide / setup / 备份同步 | 全部 | 不动 |

## 五、反馈系统（仅关键节点）

触发点（engine 返回 ok 的时刻）：完成入账、冲正、兑换、商品消费。
动作：Haptics 轻触觉（10ms，成功双击感用 notification 类型）+ 受影响余额数字滚动变色（绿/红）。
封装：`ui/helpers.js` 新增 `haptic(type)` 与 `animateBalance(resourceId)` 原语，web 端静默降级。

## 六、断裂修复清单（与手势正交，照单执行）

1. **产出链**：completeActivity 成功后浮层接续「立即发布 / 留在草稿」，发布后第二拍「归档→价值流」
2. **首启衔接**：setup 完成 → `dayGuide.maybeShow(App, {force:true})`；reset 清 `dayGuideLast`
3. **完成后接续**：Done 列头加待处理计数 chip，支持批量推进
4. **冻结出路**：blocked 卡与反馈卡加「调整预算」直达按钮
5. **仲裁接续**：「让对方先」后提供跳转到改约结果（calendar 暴露 `focusDate(k)`）
6. **逾期二次通知**：scheduler 对逾期项在 expected+24h 再发一次（幂等）
7. **dayGuide 重入**：日历页头部「🌅 今日规划」手动入口
8. **同步冲突死角**：取消后追加「先拉取合并」选项

## 七、技术要点

- 新增 `ui/gestures.js`：原生 JS 手势工具层（~150 行）：方向锁、阈值判定、长按计时器、跟手位移回调；无引导状态机
- 五态进度轨：`activityCard()` 渲染时输出 CSS 进度轨；peek 层用 transform 实现（性能纪律：只动 transform/opacity）
- 长按菜单复用现有 `.act-menu` 样式与 `closeActMenus()` 全局关闭逻辑
- 所有新引导/偏好状态只进 `Prefs`，不碰 db 八集合（备份契约 `{app,version,exportedAt,db}` 不变）
- `timer.record()` 收编进 engine（新增 `quickComplete()`），消除唯一绕过引擎的写路径

## 八、分期落地

- **一期**：手势基建 + 活动卡全语法 + 资源卡长按菜单 + 断裂修复 #1/#3/#4/#5 + 反馈系统
- **二期**：日历议程行语法 + 商品/流水统一 + 产出库视图（Draft 收件箱）+ 断裂 #2/#6/#7/#8 + 空态文案全量替换
- **三期**：顶栏瘦身、设置聚合页（数据管理/备份/同步/小组件/主题迁出统计页）、计划状态下拉改动词组

每期独立 build→sync→gradlew 打包装机验证；手感不对逐项回退（手势开关兜底）。

## 九、测试策略

- 领域层不变量测试持续全绿（现有 53 条为底线，只增不减）
- 手势工具层单元测试（node --test：方向锁/阈值/长按判定的纯函数部分）
- 每期 UI 冒烟：scripts/*.py Playwright 脚本扩展断言（单击动词生效、长按菜单可达全部旧功能）
- 真机验收清单：每期附「旧操作逐条可达」核对表（宪法 #1 的执行证明）

## 附录 A · 调研结论摘要（子代理报告）

24 条用户流程全景梳理；三类问题：
- 无入口：产出库缺失、同步服务运行态不可见、回充落账资源不透明、循环补设能力隐藏
- 深埋：冲正（无筛选账本底部）、产出发归档、数据管理四件套混居统计页、自动备份默认关
- 断裂：产出链死亡、首启衔接缺失、完成后无接续、逾期静默、冻结无出路、仲裁失联、dayGuide 跳过即失联、同步冲突死角、reset 后偏好残留
